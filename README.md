# EMtrace benchmark

Scripts, scoring library, configurations, score tables and figure code behind the benchmark in
the EMtrace manuscript. It reproduces the paper's figures and tables from the score tables in
`metrics/`, and the score tables from EMtrace and comparator runs.

EMtrace itself: <https://github.com/weinstein-bioinfo/EMtrace>.

## Contents

| Path | Contents |
|:--|:--|
| `ngs_benchmark/`, `tests/`, `pyproject.toml` | `ngs-benchmark`, the scoring library (Python package; details in [docs/ngs_benchmark.md](docs/ngs_benchmark.md)) |
| `jobs/framework_A/` | Framework A, taxonomic detection: EMtrace, EPI2ME, CZ ID, MEGAN-LR and metaMix runs, database builds, rescoring |

## Install

1. **EMtrace 1.0.0**: install from source with pip, with its external tools from Bioconda (see
   the EMtrace README), and its databases. Scripts read the database directory from `EMTRACE_DB_DIR`.
2. **Scoring library**, in the same environment:

   ```bash
   pip install -e .            # ngs-benchmark
   pytest                       # unit tests
   ```

   Taxonomy lookups for comparator outputs use EMtrace's NCBI taxonomy
   (`$EMTRACE_DB_DIR/taxonomy/ncbi/taxonomy.db`, or set `NGS_BMARK_NCBI_TAXONOMY_DB`).
3. **Comparators** (only to re-run them): EPI2ME wf-metagenomics, CZ ID (web), MEGAN-LR (LAST +
   MEGAN6, after host removal with nf-core/taxprofiler), ViMOP (Nextflow), INSaFLU-TELEVIR (web),
   Emu, Spaghetti, Kraken 2/Bracken. Versions and settings are in the manuscript's Methods
   (INSaFLU-TELEVIR: Supplementary Table 6) and in the script headers.
4. **R** (figures and tables): R 4.x with the tidyverse.

All scripts run from the repository root. Run outputs go to `results/` and logs to `logs/`
(both untracked).

## Data

Reads are not part of this repository. Public libraries are downloaded from SRA/ENA by accession
(`jobs/config.yaml`, `jobs/assets/*_accs.txt`, `data/sra/metadata/`). The simulated
divergent-virus reads are generated by `jobs/framework_B/sim_pipeline.sh` from the ViMOP benchmark
materials; the read-length/quality profile used by the simulator (`jobs/assets/pbsim_profile/`,
224 MB) is not tracked. Of the Framework C replay libraries, the tick pools are on SRA
(BioProject PRJNA878809); the KEVOOV and TBEV libraries are available from the authors on
request, so for them this repository carries the score tables (`metrics/framework_C/`) and the
scoring references (`data/*/refs/`). See the manuscript's Data availability statement for the
remaining libraries.

## Reproduce the figures and tables

From the score tables in `metrics/` (minutes):

```bash
Rscript rplots/frameworkA_detection.R
Rscript rplots/buddle_precision_recall_vs_load.R
Rscript rplots/framework_B.coverage_vs_divergence.R medaka
Rscript rplots/framework_B.errors_vs_divergence.R medaka
Rscript rplots/petersen_coverage_identity.R
Rscript rplots/gauthier_recovery_vs_ct.R
Rscript rplots/frameworkC_barcode79_stabilisation.R
Rscript rplots/frameworkC_realtime_combined.R
Rscript rplots/frameworkC_realtime_figure.R
Rscript rtables/tables.R
```

## Adapting to your system

The job scripts document what was run, with the exact commands and settings; they are not a
portable pipeline. The `*.sbatch` scripts and the 16S EMtrace scripts ran on CSC's Roihu and
Puhti clusters, Framework C and the 16S timings on a laptop. To re-run one, edit the paths and
settings at the top of the script:

- Slurm header: account (`project_XXXXXXX`), partition, time and memory;
- `EMTRACE_DB_DIR`, `databases`, `hostgenomes`: database and host-genome directories;
- `PROJ`, `PROJAPPL`: working and software directories (Roihu scratch and projappl);
- tool locations (conda environments, Apptainer images, `$PROJAPPL/install/`).

The figure and table code needs none of this: it runs from the repository root on the score
tables in `metrics/`. The scoring scripts read the run outputs from `results/`.
